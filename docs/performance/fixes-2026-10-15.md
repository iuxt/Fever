# 性能问题修复与复测 — 2026-10-15

已修复[本轮审计](./audit-2026-10-15.md)确认的 7 项问题及内存脚本故障。修改基于原工作区继续进行，保留了已有的图片目录和其他未提交改动；测试均使用示例数据或临时笔记库。

## 修复内容

| 问题 | 最终处理 |
| --- | --- |
| 历史 diff 阻塞界面 | 使用独立 Worker；切换版本、退出或超时后终止 Worker。计算限制为 300 ms / 2,000 次编辑距离，输入合计超过 2 MiB、输出超过 20,000 行或计算超限时，回退为两个版本的分页文本。界面设 1.5 秒终止兜底。历史及文件 diff 每页最多挂载 200 行。 |
| 超限文件先被读入 | 共用有字节上限的读取器，打开文件后先检查类型和大小，再分块读取；文件在检查后增长时也只读取到上限加 1 字节。导入、正文读取、搜索、仓库文件预览 / 保存检查和未跟踪文件 diff 均采用受限读取。 |
| 保存触发全文重读 | 只缓存当前查询的文件版本和匹配布尔值；按 size / mtime / ctime / inode 检查失效，正文仅重读变化文件。保持 Unicode 小写匹配、4 个并发读取和取消语义；切库时清空缓存。外部修改和删除仍有回归覆盖。 |
| 导图失败残留图片 | 写入前先校验整批格式和大小；逐张传输，避免整批二进制同时常驻。用导入标识跟踪本批新文件，失败时清理；写入途中失败也清理本次部分文件。插入草稿后若保存失败，保留草稿引用的图片用于重试，避免误删。导入期间继续允许输入和切换笔记，完成后更新原笔记。 |
| Git 列表 DOM 和查找放大 | 已暂存 / 工作区两个分组按视口挂载，保留完整计数、滚动及末行操作；标题和回收站状态改用 Map / Set 查找。 |
| 代码语言自动检测耗 CPU | 预览和富文本编辑器都对未标注 / 不支持的语言使用纯文本；超过 32 KiB 的代码块也不做语法高亮。保留原语言标记，较小且已指定语言的代码继续高亮。 |
| Git 后台重复工作 | 主进程合并同时在途的状态查询；使用 porcelain v2 一次取得分支、HEAD 和 ahead / behind，总 Git 命令由每次 4 个降为 2 个。前端完成一次查询后再安排下一次：前台 15 秒、后台页面 60 秒。相同状态复用对象，迟到响应不能覆盖较新状态；历史只在面板可见且 note / HEAD 变化时读取。 |

`tests/memory-stress.mjs` 的图片路径断言已经支持 `images/<笔记ID>/<日期>.png`，后续绘图阶段可以正常执行。

资源脚本还实际验证了生产 `dist/file://` 中的 Worker：从真实 Git 版本读取文本并显示正确的新增 / 删除行，确认没有仅在开发服务器上可用的问题。
